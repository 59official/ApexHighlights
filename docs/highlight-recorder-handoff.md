## 0. 一句话结论

一个人的项目，走**自研采集 + 磁盘环形缓冲 + 单游戏事件适配**这条路：
现金成本 0～3000 元/年（几乎只有代码签名证书），常驻内存 50～80MB、显存 150～250MB，
技术栈 C# + NativeAOT（求快）或 Rust（求极致小），**不要打包 OBS**。

## 3. 技术路线：不要打包 OBS

### 3.1 打包 OBS 的代价

- 便携模式整包塞进安装包，启动加 `--portable --startreplaybuffer`，主窗口可隐藏到托盘
- 体积：完整包 300MB+，裁剪后约 150MB
- 占用：空载 300～500MB 内存、400～800MB 显存
- 直接把「轻量化」这个目标废掉

### 3.2 GPL 合规注意

OBS 是 GPL-2.0，再分发必须附许可证与源码获取方式（指向官方仓库即可）。
外壳通过 WebSocket 通信属于进程边界之外，可闭源；**改了 OBS 源码再分发，改动部分必须开源**。

### 3.3 自研路线

Windows Graphics Capture 抓帧 → NVENC/AMF 硬编 → 环形缓冲 → 事件触发落盘。
成品 5～10MB，无第三方依赖，无 GPL 负担，代价是多花一两个月啃 D3D11 互操作与编码器复用。

## 4. 轻量化目标与实现手段

### 4.1 目标数字（1080p60）

| 指标 | 目标 |
| --- | --- |
| 常驻内存 | 50～80MB |
| 显存 | 150～250MB |
| CPU | < 3% |
| GPU 编码器占用 | 5～8% |

4K 大约翻倍。

### 4.2 四个关键手段

1. **环形缓冲不进内存**：编码后的码流 15Mbps × 60s ≈ 112MB；再进一步写磁盘临时环形文件，内存压到几兆。代价是 SSD 写入约 7GB/小时，可接受（Outplayed 就这么做）。
2. **全程 GPU 不回读**：采集纹理直接喂 NVENC，禁止 GPU→CPU→GPU 的 copy-back。
3. **UI 不用 Electron**：空壳就吃 100～200MB。用 WinUI3 / WPF / Tauri。
4. **事件检测要廉价**：单游戏优先走官方接口或日志轮询（几百 KB），图像识别用小图模板匹配，不常驻 YOLO。

### 4.3 工程约束

采集与编码放独立进程，界面崩溃不影响录制。

## 5. 语言选型

结论：**语言不是瓶颈**，运行时代价可忽略，但可以排一下。

| 语言 | 运行时开销 | 评价 |
| --- | --- | --- |
| C++ | 2～5MB（静态链接 CRT） | 最贴近 SDK，开发慢 |
| Rust | 同量级 | windows-rs 绑定成熟，内存安全，需自写 NVENC 绑定 |
| C# + NativeAOT | 15～20MB | 开发最快，Vortice / Silk.NET 可直连 D3D11，UI 顺手 |
| Go / Python | — | 跨 cgo 调 GPU 别扭，只适合原型 |

**推荐**：一个人做 → C# + NativeAOT；追求极致小 → Rust。
不建议核心 C++ + 外壳 C# 的双语言方案，维护成本会吃掉省下的内存。

## 6. 优化清单与落地顺序

四条互不冲突，但代价和顺序不同。

### 6.1 每帧零分配（地基，必须先定）

启动时按最大分辨率一次性分配纹理池、编码输入缓冲、码流槽，运行时只搬指针。
后期再改等于重写。

### 6.2 编码参数用最快预设（最便宜）

一行配置的事。关掉 lookahead 和 B 帧，同码率画质会糙，**码率从 15 提到 20Mbps 补回来**。

### 6.3 队列深度 2～4 帧

配合策略：**队列满就丢最旧帧，不阻塞采集**。
常见错误是队列一满就扩容，最后全是延迟，录下来的高光比实际晚半秒。

### 6.4 空闲释放编码会话（有冲突，最后做）

NVENC 初始化需要几十到两百毫秒，切出即释放会丢开头几帧。
正确做法：**延迟释放，空闲 5～10 分钟再关**；更稳的是保持会话但停掉编码循环。

### 6.5 已知矛盾

窗口尺寸变化时纹理池尺寸对不上，需要重建。按低频事件处理即可（几十毫秒，用户无感）。

## 7. 开源相关（已讨论，未定稿）

- 许可：MIT / Apache-2.0（利于传播，允许他人闭源再用）；AGPL（防白嫖，但公司避之）
- 若打包 OBS，安装包需满足 GPL-2.0；自研则完全绕开
- 仓库结构：采集 / 编码 / 缓冲 / 事件适配器（插件式，一游戏一目录）/ 界面 分层
- 配套：GitHub Actions（Windows runner 自动构建）、CONTRIBUTING、issue 模板、CHANGELOG
- 红线：不提交游戏客户端文件，不含反作弊逆向代码，不上传录制素材
