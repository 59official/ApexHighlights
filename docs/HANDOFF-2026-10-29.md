## 补丁：表头「全选」点不动（用户反馈「全选点不了啊其他正方形边框倒是能点」）

- **原因**：表头是 ListView 的子窗口（`SysHeader32`），点它的鼠标消息**不会**冒到 `ListView.OnMouseDown`。行里那些正方形能点是因为它们在列表客户区；表头那一格压根收不到消息，`IsCheckHit` 里那行「兜底」永远等不到调用。
- **改法**（`ClipListView.cs`）：`OnHandleCreated` 里 `SendMessage(Handle, LVM_GETHEADER, …)` 取表头句柄，用一个 `NativeWindow` 子类 `HeaderHook` 挂上去拦 `WM_LBUTTONDOWN` / `WM_LBUTTONDBLCLK`；x 落在 `2..CheckSpan+44` 就 `ToggleAll()` 并**吞掉**消息（不吞表头会顺手开始拖列宽）。`OnHandleDestroyed` 里 `ReleaseHandle`。
- **自检**：新增 `internal bool HeaderHooked` 与 `internal void TestHeaderClick(int x)`——后者真往表头窗口 `SendMessage` 一条 `WM_LBUTTONDOWN`，把钩子那条路走通。直接调 `HandleHeaderClick` 只验判断，验不到「钩子挂没挂上」，而用户报的正是挂不上。`BatchCheck` 三条断言：全勾时点表头 → 全取消（35→0）、再点 → 全勾上（35/35）、点「时间」列 → 勾选不动。
- **顺带**：`SetSelectMode` / `ToggleAll` 改用 `Invalidate(true)`，否则表头那格的金色勾不会跟着刷。
- 验证输出：`ok 点表头「全选」→ 全取消（35 → 0）` / `ok 再点表头「全选」→ 35/35 片全勾上` / `ok 点表头别处（时间列）不算全选`；全勾截图存 `captures/ui_batch_all.png`。`dist\` 已重新发布（`ApexHighlights.dll` 311808，10:07），用 `./dist/ApexHighlights.exe --ui-test --dir="D:/played/captures/clips"` 复核全绿。

# 第九轮：音轨四档 / 提示三档 / 关掉录制黄框（0.8.0）

用户提了三件事（2026-10-29 下午）：

1. 「音频录制你理解错我意思了」——不要两个勾选框，要三档：① 麦克风 + 游戏 + 系统声 ② 只录游戏内声音 ③ 系统声 + 游戏声但不含麦克风。
2. 「我不想录制时有个黄色边框」——希望像英伟达那样在右上角弹一个小窗再收回去；提示要三档（不提示 / 提示音 / 滑出浮层）。
3. 那个滑出窗口「录制最好不录制到」。

三件事都做完了，第 3 条是**天然成立**的：采集用 `CreateForWindow` 按游戏窗口的 HWND 抓，浮层是独立的顶层窗口，根本不在取景框里。

## 一、音轨：两个布尔 → 四档单选

| 菜单项 | 实际抓什么 |
|---|---|
| **只录游戏（推荐，默认）** | 进程级回环，只抓 Apex 进程树出声 |
| 系统声音 + 麦克风 | 整机回环 + 麦克风混音 |
| 系统声音（不含麦克风） | 整机回环 |
| 不录声音 | 两个源都不开（片段无音轨，体积最小） |

- `CapturePolicy.Audio` 从 `bool` 变成 `AudioMode` 枚举，另加 `NoticeMode`。**属性叫 `Audio`、JSON 键叫 `AudioMode`**（`[JsonPropertyName]`），别问我为什么，问就是两个都读着顺。
- **老配置自动迁移**：`{ "Audio": true, "Mic": false }` → `SystemOnly`（保持老行为），`(false,true)` → `SystemAndMic`，`(false,false)` → `None`。迁移必须在**反序列化之前**改写 JSON——先把 bool 喂给枚举会 `JsonException`，整份配置退回默认（用户的码率阈值一起丢）。
- **进程回环**（`Wasapi.cs`）：`ActivateAudioInterfaceAsync` + `AUDIOCLIENT_ACTIVATION_PARAMS`（12 字节 blob）+ `PROPVARIANT`（VT_BLOB），设备串 `VAD\Process_Loopback`，按 PID 含子进程树。
- **回退**：进程回环起不来（异常，或者 3 秒一个包都不来）自动退回整机回环，菜单标「音轨（只录游戏·已回退系统）」。宁可混进 Discord，也不能给用户一段无声片段。

### 这条链路的两个大坑（都是运行时才炸）

- **`[ComImport]` 的接口不能在托管代码里实现**。`IActivateAudioInterfaceCompletionHandler` 一旦标了 `[ComImport]`，CLR 拒绝为托管实现生成 CCW，运行时抛 `NotImplementedException: The method or operation is not implemented.`（E_NOTIMPL），看起来像「激活失败」。正确写法：**去掉 `[ComImport]`**，只留 `[Guid]` + `[InterfaceType(InterfaceIsIUnknown)]`。
- **COM 接口方法必须 `[PreserveSig]`**。缺了它，CLR 把失败 HRESULT 翻译成异常，所有 `if (hr < 0)` 判断都成了死代码。进程回环的 `GetMixFormat` 本来就该返回 `E_NOTIMPL`（虚拟设备没有混音格式，我们要走手搭 48k/2ch/16bit 那条分支），结果直接抛异常。四个接口共 24 个方法全补上了。

自检：`ApexHighlights.exe --audio-probe` 把探针挂在自己进程上、播一声自己的提示音，看到 `收到 30 包 / 57600 字节` 才算通。

## 二、提示：三档单选

`CapturePolicy.Notice`（默认 `Toast`）：

| 档 | 开始时 | 存好时 |
|---|---|---|
| **滑出浮层（默认）** | 右上角 `1440p · 60fps` / `ApexHighlights正在录制` | 右上角 `35 秒 · 击倒` / `ApexHighlights已录制` |
| 只响一声 | 静默 | `Beep.Saved()` 叮一声 |
| 不提示 | 静默 | 静默 |

- 新文件 `Toast.cs`：分层窗口（`WS_EX_LAYERED | WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW`），`UpdateLayeredWindow` 推 ARGB 位图，320×72、圆角 14、左边一条 3px 黄条 + 准星图标（`AppIcon.Render` 复用，不额外带图片）。
- 节奏按用户定的：**滑入 1s → 停留 1.5s → 滑出 0.5s**；点一下打开回顾库并立刻收起。
- 位置：右上角，右边距 20、顶边距 84（比英伟达那个小一圈，用户要求的）。

## 三、关掉录制黄框（B 方案：身份包 + 自签证书）

事实先摆清：**那条黄框是 Windows 11 给「正在被采集的窗口」画的系统提示**，不是我们画的，也**不进录像**（WGC 只抓窗口内容，框画在窗口外面）。想让它消失只有官方那一条路，而且三件缺一不可：

1. 包清单里声明 `graphicsCaptureWithoutBorder`（restricted capability，sideload 不需要商店审核）；
2. 运行时 `GraphicsCaptureAccess.RequestAccessAsync(Borderless)` 向用户要一次授权；
3. 用户同意后 `GraphicsCaptureSession.IsBorderRequired = false`（WGC 契约 2.0，Windows 11 才有）。

绿色 exe 没有包清单，第 1 步就过不去。所以做了个 **sparse MSIX「身份包」**：包里没有程序本体，只给安装目录里的 exe 一个包身份。

- `src/ApexHighlights/app.manifest`：side-by-side 清单，只有 `<msix publisher/packageName/applicationId>` 三个值——**必须和身份包清单一字不差**，对不上不会报错，只会「注册成功但运行时没身份」。
- `packaging/identity/AppxManifest.xml`：`AllowExternalContent=true`、`runFullTrust` + `unvirtualizedResources` + `graphicsCaptureWithoutBorder`，`AppListEntry=none`（别出现在开始菜单）。
- `packaging/make-identity.ps1`：缺证书就造（`-Type CodeSigningCert`，Subject `CN=ApexHighlights`）→ `--make-assets=` 生成商店图标 → `makeappx pack /nv` → `signtool sign`。产物 `packaging/identity/out/ApexHighlights.Identity.msix`（约 14 KB）+ `.cer`。
- `packaging/identity/register-identity.ps1`：装证书进 `LocalMachine\TrustedPeople` → 反注册旧版 → `Add-AppxPackage -ExternalLocation {app}`。**任何失败都 `exit 0`**，不然 Inno 会把安装判成失败。
- `ApexHighlights.iss`：`[Run]` 用 `Verb: runas` 拉这个脚本（弹一次 UAC），`[UninstallRun]` 反注册（普通权限就够，包是当前用户注册的）。
- `BorderlessAccess.cs`：`TryEnable(session)`，只在第一次问系统，之后走缓存；没有包身份时返回 `NotDeclaredByApp`，安静放弃、黄框照旧。

### 这一节的坑

- **自签证书放进「当前用户 → 受信任的人」不管用**：包部署服务（AppXSVC）跑在 SYSTEM 下，只认**机器级**信任。用户根存储也试过（`certutil -user -addstore -f Root` 成功、重试仍 `0x800B0109 CERT_E_UNTRUSTEDROOT`）。所以注册这一步**必须提权**，安装器里那次 UAC 就是为它弹的。
- `New-SelfSignedCertificate -Type Custom` + 基本约束扩展会造出「自签 CA」，Windows 当它是不受信任的根；改用 `-Type CodeSigningCert` 生成叶子证书。
- **PowerShell 5.1 读 UTF-8 无 BOM 的 `.ps1` 会把中文按 GBK 解**，然后报离奇的 `Missing closing '}'`。脚本一律存 UTF-8 **带 BOM**；反过来 `.msix` 里的 `AppxManifest.xml` 又**不能**带 BOM（makeappx 会抱怨 XML 声明不在第一格），用 `UTF8Encoding($false)` 写。
- `Get-PfxCertificate` 会交互式问密码，非交互环境直接报「处于非交互模式」，用 `X509Certificate2($pfx, $pwd)` 代替。

### 本机没能验到的部分

这台机器**不是管理员**（`admin=False`）、也没开开发者模式，所以 `Add-AppxPackage` 那一步在本机跑不通（`0x800B0109`）。可验的都验了：

- 身份包本身打得出来、签名成功（`signtool verify` 通过）；
- 没有包身份时程序**安静降级**（日志一行 `这个版本没有包身份，黄框关不掉（便携版正常现象）`，录制照旧）；
- 有身份的完整链路要等你在装好的机器上第一次开始录制：应当弹一次「允许无边框采集」，同意后黄框消失。

## 0.8.1：进程回环在 STA 线程上会 E_NOINTERFACE

真机日志（0.8.0，用户机器）：

```
[audio] 进程回环启动失败: Unable to cast COM object of type 'System.__ComObject' to interface
        type 'IAudioClient' … 0x80004002 (E_NOINTERFACE)
[audio] 系统声音开始采集（默认播放设备）
```

原因：托盘的「开始录制」跑在 WinForms 的 **STA** 界面线程上。`ActivateAudioInterfaceAsync`
返回的对象会被 COM 编组进 STA，而 mmdevapi 给进程回环客户端准备的代理**并不实现 IAudioClient**，
第一次碰它（`GetMixFormat` 或强转）就是 E_NOINTERFACE。我的命令行探针一直是好的，因为控制台
主线程默认就是 **MTA**——同一个 bug 在开发环境里天然看不见。

修法（`Wasapi.cs`）：进程回环的 `Start()` 把整段激活 + `GetMixFormat` + `Initialize` + `Start`
丢到一个 `ApartmentState.MTA` 的临时线程上跑完再返回（失败照常抛给调用方，好回退整机回环）；
`Dispose()` 里的 `Stop`/`ReleaseComObject` 同样回 MTA 做。

新增自检 `--audio-probe-sta`：在 STA 线程里跑同一个探针。修之前它在 `GetMixFormat` 处炸，
修之后 `收到 33 包 / 63360 字节`。**以后动这部分代码，MTA 和 STA 两种都要跑一遍。**

回退机制在这台机器上是好的：进程回环失败 → 自动改抓整机回环 → 片段照样有声（只是会混进 Discord）。

# 0.8.2：录制参数面板（滑杆）

三项需求（用户 2026-10-29 晚）：码率默认值、把「合并窗口」拆成击杀前/击杀后、开机不再弹黑框。
问过一轮（grill）之后定下来的形态是：**一个独立面板，四根滑杆，拖完立刻生效**，不进托盘菜单
（菜单里塞不下滑杆，塞进去也只能是档位列表）。

## 面板

`src/ApexHighlights/ParamsForm.cs` + `src/ApexHighlights/ParamSlider.cs`（都是自绘，不用系统 TrackBar）：

| 滑杆 | 范围 | 默认 | 落盘字段 |
|---|---|---|---|
| 比特率（Mbps） | 4–60，步进 1 | **28** | `BitrateMbps` |
| 击杀前（回放多少秒） | 0–30 | **15** | `PreRollSec` |
| 击杀后（继续录多少秒） | 0–30 | **15** | `PostRollSec` |
| 合并窗口（多久算同一场） | 0–30 | **8** | `MergeSec` |

- 0 值的括号文案：前摇 `0s（事件发生前无录制）`、后摇 `0s（事件后立即结束）`、合并 `0s（每次命中各出一段）`。
- 拖动**实时生效**，松手即写 config.json，没有「保存」按钮；底部「恢复默认」+「完成」。
- 两个入口：回顾库工具条「录制参数」（在「删除」右边）+ 托盘「录制参数…」。
- 托盘原来的「画质码率」「合并窗口」两个子菜单删掉了——同一个设置不要有两个入口。

## 前/后摇怎么生效

`Capture` 新增 `PreRollSec` / `PostRollSec`（`-1` = 沿用游戏档案里 `games/apex.json` 的值），
切片范围、后摇等待、兜底退出三处都改成读它，不再直接读 `_prof`。所以面板上的数一改，
下一段就是新长度——不用重开录制。

老配置里没有 `PreRollSec`/`PostRollSec` 时用 15/15（`CapturePolicy` 的默认值），
码率超范围（老配置可能写着 80/100）会被 `Clamp` 夹到 60，并在日志里记一句。

## 黑框没了

`<OutputType>` 从 `Exe` 改成 `WinExe`：双击、开机自启、从快捷方式启动都不再弹控制台。
自检和命令行输出靠 `AttachParentConsole()`（`AttachConsole(ATTACH_PARENT_PROCESS)`）挂回父终端。

**踩的坑**：改完 WinExe 之后 `exe --policy-test > log.txt` 得到 0 字节。因为 Attach 之后我无条件
把 `Console.Out` 重指到 `Console.OpenStandardOutput()`——重定向时 stdout 本来就是有效的文件句柄，
被我改指到控制台去了。现在 Attach 之前先看 `GetStdHandle` 是否有效，两个都有效就直接返回、什么都不动。

## 0.8.5：HUD 缩放（横幅大小）+ 简中模板

### 需求
用户的追问：「如果用户用的分辨率是 1080p 之类，和我的 2560×1440 不一样的话是不是识别不出来？」
顺带把上一轮缺的简中模板补上（用户给了 2560×1440 简中原图）。

### 先量后改（都用真截图）
| 变量 | 结果 |
|---|---|
| 分辨率（1440p / 1080p / 900p / 2160p） | 简中 0.995 / 0.979 / 0.963 / 0.992；繁中 0.999 / 0.973 / 0.944 / 0.996 —— **分辨率无关**（条带在采集时统一缩放回 1280×120 基准空间） |
| HUD 缩放 ±10% | 1.0→0.995；0.9→0.398；1.1→0.457；1.2→0.251 —— **NCC 对尺度几乎零容差** |
| 逐帧分数分布（4129 帧 / 7 个会话） | 最高 0.1923，全部 < 0.30 —— 正常对局根本进不了灰区，所以「灰区才补扫」平时零开销 |
| 单帧检测耗时 | 1.3–1.7 ms（三模板） |

### 改了什么
- `games/apex/knock-zhcn.png`（74×44，从简中原图 band 坐标 (505,16) 起裁）+ `games/apex.json` 第三条模板 `knock_zhcn`。
- `DetectPolicy.HudScalePct`（0 = 自动）与 `HudScales = {0,80,90,100,110,120}`、`HudLabel/HudHint`；`Save` 写 `HudScalePct`，`Clamp` 把乱填的值退回 0。
- `BannerEngine`：`BannerTemplate.Path`、`_base`/`_variants` 缓存、`SetHudScale(pct)`、`Variant(pct)`（按比例重采样后重算高通系数）、`ScoreScaled(band, best)`（对 80/90/110/120 四档各扫一遍取最高）、`Apply(policy)` 连 HUD 缩放一起套。
- `Capture`：`GrayFloor = 0.30f`，`HudScalePct == 0 && GrayFloor <= score < threshold` 时补扫其它尺度。
- `TrayApp`：新菜单「HUD 缩放（自动）」紧跟「检测灵敏度」，`ApplyHudScale` 写盘 + `_eng.SetHudScale`（采集进行中也立刻生效）；`_eng` 提为字段。
- `Program`：`--band-check --hud=N` 强制某档模板（验证用）；正常启动把手 `engine.SetHudScale(detect.HudScalePct)`。

### 验证
- `--band-check --hud=80/90/110/120` 对相应尺度的合成样本：0.978 / 0.968 / 0.991 / 0.985。
  （中间踩过一个假坑：整条带缩放并平移的样本上 110% 只有 0.543，换成「只缩放文字块、底色不动」的样本就是 0.991 —— 是合成样本的背景错位，不是模板的问题。）
- 英文历史 64 张 band 回归：分数与文件名里的历史值**逐张一致**，阈值 0.60 下仍是命中 47 / 挡掉 4。
- `--policy-test` 补 HUD 断言（默认自动、写盘、不冲掉阈值、乱填退回、档位表六档）后全绿；`--ocr-parse-test`、`--ui-test` 全绿。
- 托盘自检：菜单顺序 `… 检测灵敏度（0.70） / HUD 缩放（自动） / 录制参数…`，点 110% → config 写入 → 点回自动。

### 教训
- 「分辨率不同」和「HUD 缩放不同」是两件事：前者被条带归一化吃掉了，后者才是真风险。以后有人报「识别不到」，先问这两项。
- 合成测试样本要小心：缩放整条带再平移，会把横幅底板的边缘挪位置，高通之后的局部背景变了，分数就假掉。只缩放文字块、背景不动才等价。

## 0.8.6：老用户永远收不到新模板（真机事故）+ 识别诊断脚本

### 事故现象
用户在 0.8.5 上连续击倒 6 次，一次都没录上（游戏语言：简体中文）。版本号确认是 0.8.5.0，不是「装旧了」。

### 根因
`Paths.EnsureGames()` 释放内嵌 `games/` 资源时是 `if (File.Exists(dst)) continue;` —— **存在就不覆盖**。
所以 0.8.4 加的繁中模板、0.8.5 加的简中模板：图片文件（新文件名）确实被释放进去了，
但**注册模板的 `templates` 数组写在 `games/apex.json` 里，而老用户这份 json 从第一次安装起就没再动过**。
结果：程序升级了，模板还是只有英文一条，中文局一次都认不出来——版本号却是新的，极容易被当成「识别坏了」。

实测证据（用户机器 `E:\ApexHighlights`）：
- `games/apex.json` 422 字节、mtime 19:31（首次安装），`templates` 只有一条 `{"id":"knock","file":"apex/knock.png"}`
- `games/apex/` 里 `knock-zhcn.png`（22:38）、`knock-zhtw.png`（22:38）都在
→ 图片到了，注册没到。

### 修法
`Paths.EnsureGames()` 末尾追加 `MergeNewTemplates()`：把内嵌配置里**新增的模板**并进用户那份 json，
只追加不覆盖（band、阈值、用户自建模板全部原样保留）。判重同时看 `id` 和 `file`
（老英文模板 id 叫 `knock`，新版叫 `knock_en`，只比 id 会把同一张图加两遍）。
合并成功会写一行日志：`[games] apex.json 补进 2 个新模板：knock_zhtw, knock_zhcn（其余设置保持原样）`。

验证：拿用户那份旧 json 放进临时数据目录跑一次 → `templates` 变成
`[('knock','apex/knock.png'),('knock_zhtw',...),('knock_zhcn',...)]`，`band` 与 `preRollSec: 30` 原样。

### 新工具：诊断-识别.bat + --diag-report
用户要求「像当初搞英文锚点那样，先给个 .bat 测一下」。做了两半：

1. `诊断-识别.bat`（跟便携版一起发到 dist/）：`诊断-识别.bat [秒数]` 默认 60 秒，
   跑 `--log=captures\diag\diag.log --duration=N`，结束后自动调 `--diag-report`。
2. `--diag-report=<目录或csv>`（`src/ApexHighlights/DiagReport.cs`）：读逐帧 CSV
   （`毫秒,分数,x,y`），打印程序版本、模板清单+阈值、HUD 档、OCR 可用语言、
   最高分与 P95、分数分布四桶、一句结论，并列出 `diag_top*.bmp`。
   结论分四档：有帧过阈值（检测通，漏在别处）/ 卡灰区 0.30–0.60（多半 HUD 缩放）/
   0.20–0.30（位置偏或字体不对）/ 接近噪声（没录到游戏画面）。
3. `Capture` 在诊断模式下留存**分数最高的 5 帧条带**，退出时写成
   `diag_top1_0.53_x505_y16.bmp`（8bpp 灰度，`DiagReport.WriteGrayBmp` 手写 BMP 头），
   这样「为什么没认出来」可以直接看图。

### 踩坑
- `.bat` 必须是 **CRLF**：LF 换行的 bat 在 cmd 里会把 `if not exist (...)` 块解析歪，
  表现为「明明 exe 就在旁边，却报找不到」。
- 诊断 bat 里 `--duration` 只在「找到窗口开始录」后计时；没开游戏时会一直等着，
  所以脚本里加了 3 秒倒计时提示先切进游戏。

## 0.8.7：启动早期的日志不该凭空消失

用户装完 0.8.6 后贴日志问「这里吗好像没有诶」——看不到 `[games] apex.json 补进 2 个新模板`。
**合并其实做了**（他的 `apex.json` 从 422 → 772 字节，模板三条齐了，`band`/`preRollSec: 30` 原样保留），
问题是 `Paths.EnsureGames()` 在 `Program.cs:103` 执行，比 `Log.Init()` 早，
那行 `Log.Write` 落地时文件还没打开，被静默丢掉。用户看不见、我也看不见，这种「做了但没说」最难查。

修法（`src/ApexHighlights/Log.cs`）：`Init` 之前写的行先攒进 `Pending`（上限 200 行），
`Init` 打开文件后紧跟着补写（缩进 8 格，让人一眼看出是启动早期），
`Write` 里文件还没开就入队而不是丢弃。

验证：把配置改回「只有英文一条」的老状态再跑 →

## 0.8.8：真机日志复盘后的三处修正

用户拿 0.8.6 打了一局（14 分钟、18 次击倒、战绩 14/3/18）并把 `E:\ApexHighlights\live.log` 给我。
结论：**检测端没漏**——26 次命中、10 次被合并窗口吞掉、落下 16 片，分数 0.76–0.99（阈值 0.70），
没有误报；18 次击倒少 2 片是「8 秒合并窗口把相邻两次击倒并成一段」，不是识别问题（想一段一击倒就把合并窗口调到 3s）。
顺带修三处：

1. **`ocrErr=没装繁体中文语言包…` 在简体局也刷屏**：这句其实是「装了更准」的提示，不是错误。
   拆成 `BannerOcr.Hint`，只在第一次 OCR 时写一行 `[ocr] …`，不再进每 5 秒的 `[stat]`。
2. **合并时「种类取 未识别」**：最高分那帧可能正好被人物挡住，OCR 返回 Unknown，助攻击倒就被写成普通击倒
   （文件名少 `_ak_`）。现在若最高分帧判不出来，会按分数再试最多 2 帧，拿到种类就收手。
3. **检测 28ms/帧**（真机 `[stat]`：采样 9235 帧，均值 28.4ms）：补扫一轮是 4 档 × 3 张模板 = 12 遍 NCC，
   横幅淡出/半截露出/别的 UI 文字都会掉进灰区，那几帧每帧白扫 12 遍。
   改成「连续两帧都在灰区 + 距上次补扫 ≥150ms」才补扫，灰区下限 0.30 → 0.40，
   并在 `[stat]` 里加 `灰扫=N` 便于下次复盘确认。

验证：build 0 error；`--policy-test` / `--ocr-parse-test` / `--ui-test` 全绿。
（本机环境枚举不到窗口，`检测=` 与 `灰扫=` 的真机数字要等用户下一局日志。）

## 0.8.10：高 DPI 适配（125% / 150% 缩放下切字）

真机截图暴露的问题：系统缩放 150% 时，字号被系统放大 1.5 倍，而布局全是按 96 DPI 写死的整数像素——
参数面板副标题被切掉半行，回顾库的时间/种类/分数/时长全挤成「10-28 21:3…」「助攻…」「0.…」。

改法一句话：**所有自绘布局尺寸都过一遍 `UiKit.Px(control, 设计像素)`**。

| 文件 | 改动 |
| --- | --- |
| `src/ApexHighlights/UiKit.cs` | 新增 `Dpi(Control)` 与 `Px(Control,int)` |
| `ParamsForm.cs` | `S => DeviceDpi/96f` + `Si()`；`AutoScaleMode.None`；标题/副标题改成先 `MeasureText` 再画 |
| `ParamSlider.cs` | 轨道/滑块/标签尺寸过 `Si`，`X0/X1/TrackTop` 改成按缩放算的属性 |
| `ClipListView.cs` | `ThumbW/ThumbH/TextInset/Check*` 由 const 改 DPI 属性；建列宽过 `Px`；`FitNameColumn` 留出竖滚动条宽度 |
| `LibraryForm.cs` | 窗口 `Size/MinimumSize` 过 `Px`；`LayoutBands()` 里所有常量走局部 `z()` |
| `ClipDetailPane.cs` | 卡片内边距、预览高度、键值表 `RowHeight/KeyWidth`、底部提示高度全过 `Px` |

教训：
- 只要有一处漏了 `Px`，150% 下就会当场露馅——**改完必须在本机 150% 出图看一眼**，别只看 100%。
- `ClipListView.DrawCheck` 原来是 `static`，属性化之后必须改成实例方法（`CS0120`）。
- 表格最后一列要减掉 `SystemInformation.VerticalScrollBarWidth`，否则 150% 下会多出一条横向滚动条。

验证：`--shot-params` 780x588、`--lib-ui --shot=` 2040x1140 两张图逐列核对；`--ui-test` 76 条、`--policy-test`、`--ocr-parse-test` 全绿。

## 0.8.11：系统要求写清楚（Windows 10 支持范围）

结论先说：**Windows 10 2004（build 19041）及以上可以装、可以用**，但「录制的黄框」在 Windows 10 上关不掉。

| 能力 | 需要的系统 | 说明 |
| --- | --- | --- |
| 录屏（WGC 按窗口抓） | Win10 1803+ | 一直在用 |
| 只录游戏声音（进程回环） | **Win10 2004 (19041)** | `ActivateAudioInterfaceAsync` + `VAD\Process_Loopback`；更早的系统起不来，会自动回退整机回环 |
| 麦克风混音 | Win10 2004 同一条链路 | 同上 |
| 无边框采集（关黄框） | **Win11 22H2 (22000)** | Win10 根本没有 `IsBorderRequired` / `GraphicsCaptureAccess` 这套 API |

改动：
- `packaging/ApexHighlights.iss`：`MinVersion=10.0.17763` → **`10.0.19041`**（原来允许 1809/1903 装，但那些系统上进程回环必然失败）；`[Run]` 里注册身份包那步加 `Check: IsWin11`（新增 `function IsWin11()` 用 `GetWindowsVersionEx` 判 build >= 22000），Win10 用户不再白点一次 UAC。
- `src/ApexHighlights/BorderlessAccess.cs`：版本判断提到最外层（`OperatingSystem.IsWindowsVersionAtLeast(10, 0, 22000)` 不满足就直接返回，并记一行「Windows 10 没有关框 API，黄框会一直在」），Win11 那段搬到 `[MethodImpl(NoInlining)] TryEnableWin11()`，避免 Win10 的 JIT 顺手加载 Win11 才有的类型。

证据：OBS 官方在同样的问题上给的结论一致——"[The yellow border is already disabled automatically by our code when running on Windows 11. The linked API does not exist on Windows 10 and therefore the border cannot be disabled.](https://obsproject.com/forum/threads/yellow-border.162264/post-595342)"

验证：build 0 error；`--ocr-parse-test` 通过；0.8.11 静默安装 478 文件 / `0.8.11.0` / 卸载干净。
