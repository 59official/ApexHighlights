## 改了哪些文件（`src/ApexHighlights/`）

- **`CapturePolicy.cs`（新）**：`BitrateMbps` / `Audio` / `BitrateBps`；`Load` 容错、`Save` 只写自己两个字段（配额、阈值、合并窗口都不碰）、`Clamp`（5–200 Mbps、音轨就是 bool）、`BitratePresets`、`HintForBitrate`。照 `DetectPolicy.cs` 的范式。
- **`Capture.cs`**：`SetBitrate(int bps)`（重建 `EncoderChain`，用 `_encSwap` 锁换引用，先锁外建好再换，编码线程提交时也持同一把锁）、`SetAudioEnabled(bool)` + `AudioOn` + 私有 `StartAudio()`/`StopAudio()`（音频块从 `EnableEncoding` 抽出来，重开时重置 `_audioStart100`/`_audioFedFrames`/`_silenceFilled`，否则会一次补进整场静音）；`_audioFillRun` 独立于 `_stop`，`Stats()` 无音轨时打「音频=关」。
- **`EncoderChain.cs`**：`Dispose()` 空安全（`_next?.Result?.Dispose()` 在后台任务失败/未完成时会抛或阻塞 —— 换码率必踩）。
- **`TrayApp.cs`**：删掉 `_bitrate` / `_audio` 两个字段，改成只读 `_capture`（`CapturePolicy`）这一个真相；`BuildBitrateMenu()` / `ApplyBitrate()` / `BuildAudioMenu()` / `ApplyAudio()` 照抄 `BuildMergeMenu()` / `ApplyMerge()` 的形状；自检钩子 `FindBitrateRoot/ClickBitrate/FindAudioRoot/ClickAudio`，`ArmSelfTest()` 的 case 3 现在也把码率、音轨点一遍（含关掉再开回来，验证 `StopAudio/StartAudio` 往返）。
- **`Program.cs`**：`--bitrate=` 给过才覆盖（`bitrateGiven`），`CapturePolicy.Load(cfg)` 读配置 → 命令行覆盖 → `Clamp` → 同时喂给采集器和托盘；`Live(...)`/`RunTray(...)` 多带一个 `CapturePolicy` 参数，`new TrayApp(...)` 不再传 bitrate/audio。启动日志加 `[2d]`（码率）、`[2e]`（音轨），写法照 `[2b]/[2c]`。
- **`PillSelect.cs`**：`enum Ease { OutCubic, OutQuint, OutBack, InCubic }` + `EaseAt(Ease, double p)` + `Backness = 2.0`；`Animate(..., Ease ease = Ease.OutCubic)`。常量现在是 `OpenMs=380 / CloseMs=220 / SlideDist=10 / LeaveDelayMs=1000`。
